# v0.24 validation

## v0.24.0 release preparation

The release source baseline is `0597565259d50ba28b1935bab23f5e668366c506`.
The release changes update the package version to `0.24.0`, contributor credits,
and release documentation. They do not change production behavior.

On 2026-09-16, the operator explicitly accepted the documented limitations for
v0.24.0, including incorrect streaming counters (#818), optimized-test fixture
gaps (#819), and unmeasured HEIF memory and worker-budget risks (#761/#817).
This accepts those risks for this release; it does not establish a memory
ceiling, fix the counters, or turn unavailable checks into passes. The operator
separately approved tagging and publication after reviewing the release diff
and local validation results.

The recorded full-test run on the clean source baseline passed 21 phases and
counted 7,348 tests, including authenticated live tests. One live HEIF test was
skipped with operator approval because its fixture was unavailable. The run
started and ended at the same commit. This evidence predates the version change;
it is not a new full-test run on the release commit.

Expected repair refusals were checked separately: standalone capture repair and
conflicting refresh/recent, truncated/refresh, and truncated/dry-run flags exit 2.
Service refresh, service truncated repair, and capture repair without the
datetime writer exit 1 before authentication. The help regression test covers
both the sync and shared service help. The guide must omit `albums` and
`smart_folders` keys entirely: explicit `all`/`none` still reject full refresh.

Docker's shipped CMD is `service run --config /config/config.toml`. Generated
systemd, launchd, and Windows arguments use `service run --config <path>`.
Systemd uses `Restart=on-failure`; launchd uses a NetworkState KeepAlive condition;
Windows configures SCM failure actions. Compose uses `restart: unless-stopped`,
which also restarts after terminal-auth exit 4. These policies do not establish
backup completeness. Linux renderer tests run in the gate; macOS/Windows runtime
installation is not claimed on this Linux host.

The Homebrew formula installs `kei` into `bin` from versioned release archives.
Final tags, checksums, Docker platforms, and package versions belong to the release
owner. Source/default-feature builds do not validate every published package.

`KEI_REQUEST_DUMP_DIR` remains a debug-assertion-only diagnostic. Its Photos
bodies are unredacted and require private local storage and manual redaction
before sharing. Release builds without debug assertions do not provide it.
It is not a redacted doctor bundle.
